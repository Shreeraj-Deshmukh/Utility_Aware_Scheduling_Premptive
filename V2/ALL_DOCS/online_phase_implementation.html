1. Architecture at a Glance

The online phase sits on top of a finished offline schedule and reacts to jobs completing early. It is split into a one-time precompute and a per-event runtime:

# OFFLINE (once) v5b pipeline ──► (seg_k, freq_idx, mapping) # the schedule to protect + improve │ ▼ build_processor_dp(x) for each processor x # exact breakpoint value fn, all EDF suffixes │ # RUNTIME (per early completion, microseconds for the lookup) job (i,j) finishes at ACET < WCET │ windfall (Δt local, Δe global) ▼ OnlineController.on_completion(i,j,Δt,Δe) 1 refund Δe to the shared pool (atomic) 2 arbitrate this proc's energy claim by future utility density 3 DP lookup + reconstruct downstream (k,z) decisions 4 commit-with-guarantee: per-processor DBF + atomic pool spend 5 rebuild this processor's DP │ ▼ committed [JobDecision...]
Two resources, two regimes. Time slack is processor-local — each processor's DP and DBF touch only its own jobs, so no locking is needed. Energy slack is a single global pool shared by every processor's DP, so it — and only it — is guarded by a semaphore.

4. DP Core — Exact Breakpoint Value Function

The paper's table V[j][Δt][Δe] is, for fixed j, a step function: non-decreasing in both axes, with jumps only at reachable cost vectors. Instead of a dense grid (which would force quantising float costs), a level is stored as its Pareto frontier of requirement tuples — the list of Entry. This is exact and naturally sparse.

The recurrence — compose()

def compose(actions, downstream, tol=_TOL):
    cand = []
    for (a_t, a_e, gain, k, z) in actions:
        for d_idx, d in enumerate(downstream):
            req_t = a_t + d.req_t
            req_e = a_e + d.req_e
            if req_t < 0.0: req_t = 0.0        # clamp: surplus this job frees is unusable by the sub-chain
            if req_e < 0.0: req_e = 0.0
            cand.append(Entry(req_t, req_e, gain + d.value, k=k, z=z, a_t=a_t, a_e=a_e, nxt=d_idx))
    return prune(cand, tol)

Each candidate = "this job takes action (a_t,a_e,gain), then the rest of the chain achieves d.value needing d.req_t/d.req_e." The signed deltas let a frequency change reduce the requirement (Option 4 frees time; Option 3 frees energy) — that is how conversion enters. The max(0, …) clamp is correct because the downstream level already encodes the minimal requirement per value level.

Pareto pruning — prune()

Sort by (req_t↑, req_e↑, value↓); keep an entry only if no kept entry dominates it (≤ on both requirements and ≥ on value), and drop any kept entry the newcomer dominates. The (0,0,0) "do-nothing" entry always survives, so a query never fails.

Online lookup — query()

def query(level, dt, de):
    # best value among entries with req_t ≤ dt and req_e ≤ de; tie → smallest requirement

Building each level is compose; answering a completion is one query (O(frontier size)) plus a pointer walk.

5. The 4-Option Action Set — actions.py

For a job whose offline decision is (k_off, z_off), an online action re-selects a target (k′ ≥ k_off, z′). Relative to the baseline:

a_t = e_eff(cum[k′], fz′) − e_eff(cum[k_off], fz_off)   •   a_e = E(cum[k′], fz′) − E(cum[k_off], fz_off)   •   gain = ui · (cum[k′] − cum[k_off]) ≥ 0
Sign patternPaper option
k′>k_off, z′=z_off  (a_t>0, a_e>0, gain>0)2 — spend on segments
k′=k_off, z′=z_off  (0,0,0)1 — save (the mandatory no-op)
k′=k_off, z′<z_off  (a_t>0, a_e<0)3 — time→energy (slower)
k′=k_off, z′>z_off  (a_t<0, a_e>0)4 — energy→time (faster)

build_job_actions enumerates all (k, z), keeps only actions whose added effective time fits the job's time_cap (the timing gate; a negative a_t always passes), and returns them baseline-first. Energy is not gated here — it is global and handled by the DP state req_e and the pool.

Note on the current constants. With α=1, β=0.5 energy is minimised at fmax, so every Option-3/4 conversion action has gain 0 and a non-improving (req_t, req_e) — it is dominated by (0,0,0) and pruned away. The machinery is general; on this instance it collapses to Save + Spend.

6. Per-Processor DP Build & Reconstruction — dp.py

Building every suffix, right to left

# build_processor_dp(x, ...)
jobs_x = _edf_order(...)              # sort by (deadline, release, i, j)
V_levels[N] = base_level()            # no jobs left → single zero entry
for s in range(N-1, -1, -1):
    acts = build_job_actions(slot.i, slot.k_off, slot.z_off, cum, N_seg[slot.i],
                             freq_set, u_i, slot.time_cap)
    V_levels[s] = compose(acts, V_levels[s+1])

V_levels[s] is the value function over jobs[s:]. Because it is built for every suffix, one precompute answers every future completion point: when the job at position c completes, distribute its windfall over jobs[c+1:] using V_levels[c+1].

The time cap that matters at runtime

The controller passes time_caps = {(i,j): d − r} (the deadline interval). At the offline-committed state the static min_slack_for_job is ≈ 0 (Phase 5 ate it), so using it would let nothing through. The deadline interval is the loosest structural cap; the true per-window feasibility is enforced later at commit.

Reconstruction — ProcessorDP.distribute()

Query V_levels[start] at (dt, de), then follow Entry.nxt down the chain, emitting a PlannedAction for every job whose chosen (k, z) differs from its baseline. Returns (total_value, [PlannedAction…]).

7. Shared Energy Pool + Semaphore — energy_pool.py

The one variable shared by all per-processor DPs. It is wrapped so that every read-modify-write is atomic under a binary semaphore (threading.Lock == a mutex).

class SharedEnergyPool:
    def refund(self, amount):           # atomic += (a job finished under budget)
        with self._sem:
            self._level += amount; return self._level

    def try_spend(self, amount, tol=1e-6):  # the hard energy gate
        with self._sem:
            if self._level - amount >= -tol:  # atomic check-AND-deduct
                self._level -= amount; return True
            return False

    def try_spend_batch(self, amounts):    # all-or-nothing for the commit fast path
        return self.try_spend(sum(amounts))

    def level(self): ...   # guarded snapshot read
    def stats(self): ...   # acquisitions / spent / refunded / denied
Why fine-grained. Only the pool's check-and-deduct/refund is inside the lock. Arbitration, DP lookup, the per-processor DBF, and applying seg_k/freq_idx stay outside it — maximising concurrency and keeping contention to the single float.
Why try_spend is the correctness gate. Arbitration reads a pool snapshot (advisory). Between that snapshot and the commit, another processor could spend. Because the check and the deduction happen together under the lock, try_spend can never let global consumption exceed the budget — so C3 (total energy ≤ B) is race-proof. In the current deterministic single-thread driver there is no interleaving (denied = 0), but the guarantee already holds if you switch to one thread per processor.

Instrumentation (stats()) proves the guard is exercised — the demo reports the acquisition count, total spent/refunded, and how many spends were denied.

8. Density Arbitration — density.py

When several processors could spend the same energy, priority goes to the one with more valuable upcoming work (the paper's "higher density in the future"):

ρx(t) = Σ(i,j) on x, ri,j ≥ t   ui · (cum[i][N_seg] − cum[i][seg_k]) / pi

future_utility_density uses the current committed seg_k, so it reflects what is still addable. arbitrate_energy(pool, densities, mode) then splits the pool: "proportional" gives each processor pool · ρx / Σρ (the default), "strict" gives the whole pool to the top-ρ processor. If all densities are ~0 the pool is shared equally.

9. The Runtime Controller — controller.py

Owns the live seg_k/freq_idx/mapping, one ProcessorDP per processor, the SharedEnergyPool, and eff_override (actual effective times of completed jobs). The whole event is these five steps:

def on_completion(self, i, j, observed_dt, observed_de):
    x = self.proc_jobs_map[(i,j)]; c = self.pos_of[(i,j)]

    # 1) record the completed job's ACTUAL (reduced) execution + free energy
    committed_eff = cum[i][seg_k[(i,j)]] / freq_set[freq_idx[(i,j)]]
    self.eff_override[(i,j)] = max(0.0, committed_eff - observed_dt)
    self.pool.refund(observed_de)                          # atomic

    # 2) arbitrate this processor's claim from a LIVE pool snapshot
    pool_now  = self.pool.level()
    caps      = arbitrate_energy(pool_now, self._densities(t), self.arbitration)
    de_budget = min(pool_now, max(0.0, caps.get(x, 0.0)))

    # 3) DP lookup + reconstruction for jobs[c+1:]
    _, planned = self.dps[x].distribute(c+1, observed_dt, de_budget)

    # 4) hard-verify + commit (per-processor DBF + atomic spend), trimming if needed
    committed = self._commit_with_guarantee(x, planned)

    # 5) rebuild this processor's DP so later completions stay exact
    self.dps[x] = self._build_dp(x)

Per-processor dynamic DBF

_timing_ok_dynamic(only_x=x) checks the preemptive-EDF windows of only the committing processor, charging each job its _eff — the reduced actual time for completed jobs, full committed time for the rest. Because timing is per-processor once the mapping is fixed, this is both cheaper and lock-free (it never reads another processor's live state).

Commit-with-guarantee

def _commit_with_guarantee(self, x, planned):
    # FAST PATH: apply all; if per-proc DBF holds, claim the batch atomically
    apply all (seg_k, freq_idx)
    if self._timing_ok_dynamic(only_x=x) and self.pool.try_spend_batch([d.a_e ...]):
        return list(planned)
    revert all
    # GREEDY: highest-gain first; timing FIRST (lock-free), then atomic spend
    for d in sorted(planned, key=lambda p: -p.gain):
        apply d
        if self._timing_ok_dynamic(only_x=x) and self.pool.try_spend(d.a_e):
            keep d
        else:
            revert d          # timing checked before spending → nothing to refund
Ordering is deliberate: timing (cheap, lock-free) is checked before touching the pool, so a rejected decision never spends energy and never needs a refund. The committed schedule always satisfies timing and the global energy budget. Nothing is probabilistic — every decision is the DP optimum, committed only if it provably holds.

The two energy numbers

total_energy() is the WCET commitment; B − pool.level() is the realised consumption. They diverge by the freed energy: pool + total_energy() = B + Σδe. C3 binds on the realised number, which is always ≤ B; the WCET number may print above B (a bookkeeping artifact of pretending early-finishers ran to WCET).

10. ACET Model & Simulator — simulator.py

testcase.py holds only WCET, so the simulator synthesises ACET:

# ACET = ratio × committed effective time  →  windfall is the freed (1-ratio) fraction
ratio = acet_ratio or rng.uniform(ratio_min, ratio_max)   # default 0.7; seeded
dt = (1 - ratio) * e_eff(cum[i][k], f_z)      # local time slack
de = (1 - ratio) * E   (cum[i][k], f_z)       # energy returned to the pool

run() processes jobs in release order, calls on_completion for each, and prints a per-event line plus a summary (added utility, realised vs WCET energy, feasibility, and the semaphore stats). verify_single checks one windfall against the DP value, asserting added ≤ dp_value (the DP value is an optimistic ceiling; the commit may trim a shared-window conflict). The controller is agnostic to how (dt, de) arise — feed it real measured slack and nothing else changes.

11. Worked-Example Verification — worked_examples.py

The DP core is model-agnostic (it consumes raw Action tuples). This module feeds it the design document's own two examples (3-job and 4-job, single frequency, energy = time) and asserts that every cell of every published table V[1]…V[4] and all three traces (19.0 / 17.0 / 10.0) reproduce exactly. It runs first in the demo, so one command proves both that the DP matches the paper and that the online phase improves a real schedule.

13. How to Run

# Full online phase: verify DP vs paper → build offline (v5b) → simulate online
python run.py testcase.py online

# Just the DP core vs the design document's worked examples
python -m usrt.online.worked_examples

Configuration knobs live in SimConfig (in online_demo.py): acet_ratio (fixed 0.7, or None to draw from [ratio_min, ratio_max] with seed), and arbitration ("proportional" or "strict").
