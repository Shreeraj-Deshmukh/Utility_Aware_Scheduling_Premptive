Two documented generator caveats appear in this run. The n_prc sweep scales n_tsk with the core count (8→12→23), because U_M = α·N_prc cannot fit in a fixed task count — so that row is "effect of cores with a proportionally larger task set". And at α=0.1/0.2 the per-task δ cap is arithmetically impossible (it needs β ≤ 2α/(1−α)), so those configurations carry donate_ok=0.
v3, v4 and v5a lack Phase 6b. Their columns therefore conflate a mapping change with a missing phase, and are not directly comparable with v5b/v6/v7/claudeopt. Audit issue B2, still open.
