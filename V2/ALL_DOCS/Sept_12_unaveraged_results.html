How runtime is computed, and why it is not a plain mean. A naive average over all n instances is wrong here in three separate ways, each of which flatters the worst solvers:
  • Infeasible runs are excluded. A solver that bails out did not do the work. Its short runtime would drag the statistic down — so failing more would look like being faster. Runtime is computed only over the instances a model actually solved, and the denominator for each model is its own solved count, printed in the table.
  • Censored runs are excluded. A run that hits the time limit reports the CAP, not its cost; the true value is unknown and larger. Averaging it in makes a solver that times out appear faster than one that finishes.
  • Median, p95 and max — not the mean. These distributions have heavy tails (a single measurement was once wrong by 97×). The mean tracks the tail; the median tracks the typical case. Both the typical case and the tail are reported, rather than one number hiding the other.
Because each model then has a different denominator, a second block reports runtime over the common subset — the instances every model solved — which is the only strictly like-for-like comparison.
