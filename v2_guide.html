V2 — Commands, Modularity & Wiring

Everything you need to run, understand, and extend the USRT solver suite
The V2 folder is a clean Python package. A single entry point (run.py) drives every solver. Under the hood, each solver is assembled from small, independent modules (mapping, phases, DBF checks) like Lego bricks.

1. Quick Start

All commands must be run from inside the V2/ folder. The package imports use usrt.* paths which resolve relative to V2.
# Navigate to V2 first PS C:\homogenous> cd V2 # Run default solver (heuristic_v4) on the included testcase PS C:\homogenous\V2> python run.py testcase.py # Run a specific solver PS C:\homogenous\V2> python run.py testcase.py heuristic_v5a # Run with ILP (requires Gurobi licence) PS C:\homogenous\V2> python run.py testcase.py ilp_v2

2. All Commands

General Form

PS C:\homogenous\V2> python run.py <testcase_file> [solver_name]
  • <testcase_file> — path to a Python file that defines processors, tasks, and B_BUDGET
  • [solver_name] — optional; defaults to heuristic_v4 if omitted
## ---- Heuristic Solvers ---- ## PS C:\homogenous\V2> python run.py testcase.py heuristic_v1 # Single-pass SPS + ScheduleState pipeline (oldest, simplest) PS C:\homogenous\V2> python run.py testcase.py heuristic_v2 # Quantum SPS + left-shift greedy (3-step cases) PS C:\homogenous\V2> python run.py testcase.py heuristic_v3 # Quantum SPS + DBF window-slack greedy, Phases 1-5 (no swap) PS C:\homogenous\V2> python run.py testcase.py heuristic_v4 # Quantum SPS + DBF greedy + swap, Phases 1-6 (recommended baseline) PS C:\homogenous\V2> python run.py testcase.py heuristic_v5a # v4 + Refine Mapping 2a (linear doublet scan) between Phase 1 and 2 PS C:\homogenous\V2> python run.py testcase.py heuristic_v5b # v4 + Refine Mapping 2b (one-swap-one-scan) between Phase 1 and 2 PS C:\homogenous\V2> python run.py testcase.py heuristic_claudeoptimal # v4 + Phase 7 (double-giver swap) + Phase 8 (iterated greedy) ## ---- ILP Solver ---- ## PS C:\homogenous\V2> python run.py testcase.py ilp_v2 # Quantum SPS mapping (Phase 1) + Gurobi ILP optimisation (Phase 2) # Requires: pip install gurobipy + valid Gurobi licence ## ---- Help ---- ## PS C:\homogenous\V2> python run.py # Prints usage and lists all available solver names
Tip: To compare solvers, run the same testcase.py with different solver names and compare the final utility and energy values printed at the end of each run.

5. Lego Modularity — The Architecture

The codebase is structured like Lego: each brick (module) does exactly one thing and can be plugged into any solver. Solvers are just sequences of bricks. Adding a new solver means writing a new run() function that calls the bricks in a different order or with different parameters.

Key insight: Every phase module is stateless relative to other phases. It receives its inputs as function arguments and returns results. No global state, no hidden coupling. This means you can run Phase 5 alone, test Phase 6 in isolation, or skip Phase 4 entirely by just not calling it — the data structures stay consistent.

6. Wiring Detail — What Each Brick Picks Up From Where

Below is an exhaustive list of every import in the solver pipeline and what it contributes. Think of each row as one Lego stud connection.

Brick (import) Source module What it provides Who uses it
ALPHA, BETA usrt/models.py Energy model constants (default: ALPHA=1.0, BETA=0.5) All solvers (for print context), aggressive.py, greedy.py
total_energy() usrt/models.py Sums E = ALPHA * f^BETA * e_exec across all jobs/segments energy_slack.py, aggressive.py, greedy.py, swap.py, solvers
total_utility() usrt/models.py Sums u_i * cum[i][k_ij] / cum[i][N_seg] across all jobs All solvers (for final reporting)
load_testcase() usrt/utils.py Reads a testcase .py file; returns processors, tasks, B_BUDGET run.py (once at startup)
lcm_list(), gcd_list() usrt/utils.py Compute hyperperiod h = lcm(periods), quantum = gcd(periods) All solvers
build_cum() usrt/utils.py Builds cum[i][k] = e_{i,0} + ... + e_{i,k-1} cumulative table All solvers; used by every phase and mapping module
build_job_times() usrt/utils.py Returns job_r[(i,j)] = release time, job_d[(i,j)] = deadline for each job All solvers; used by Phase 1b, DBF checks, Phase 5, Phase 6
build_proc_jobs() usrt/utils.py Inverts mapping → proc_jobs[x] = [(i,j),...] and proc_jobs_map for fast lookup All solvers after Phase 1 (and again after Phase 1b in v5)
print_instance_summary() usrt/output.py Prints task table, processor specs, budget, hyperperiod info All solvers (once at start)
print_schedule() usrt/output.py Prints final per-job scheduling result: freq, segment count, energy, utility All solvers (at end)
quantum_sps_mapping() usrt/mapping/quantum.py Phase 1: assigns each job to a processor using Quantum SPS. Returns mapping dict. v3, v4, v5a, v5b, claudeoptimal, ilp_v2
refine_mapping_2a() usrt/mapping/refine_mapping.py Phase 1b: linear doublet scan to balance UD(x) heuristic_v5a only
refine_mapping_2b() usrt/mapping/refine_mapping.py Phase 1b: iterative greedy swap targeting max-UD processor heuristic_v5b only
left_shift() usrt/phases/left_shift.py Phase 2: simulate mandatory-only EDF at f_max; compute slack per job v3, v4, v5a, v5b
compute_energy_slack() usrt/phases/energy_slack.py Phase 3: returns (E_mandatory, E_slack = B_BUDGET - E_mandatory) v3, v4, v5a, v5b
phase_aggressive_scaling() usrt/phases/aggressive.py Phase 4: lowers frequency of eligible jobs to free energy v3, v4, v5a, v5b
phase_optional_segments() usrt/phases/greedy.py Phase 5: greedy optional segment addition gated by DBF window slack v3, v4, v5a, v5b, claudeoptimal
phase_swap_local_search() usrt/phases/swap.py Phase 6: best-first pairwise giver/receiver swap + Phase 5 fill pass v4, v5a, v5b, claudeoptimal

7. Core Data Structures — What Flows Between Bricks

Primary Data Structures

VariableTypeWhat It IsCreated By
tasks list of dict Task parameters: p_i, e_m, u_i, segments list, etc. load_testcase()
processors list of dict Processor specs: frequencies list, power curve params load_testcase()
cum[i][k] list of lists Cumulative exec time: cum[i][0]=0, cum[i][k]=e_{i,0}+...+e_{i,k-1} build_cum()
N_seg[i] list of int Number of segments for task i build_cum()
job_r[(i,j)] dict Release time of job j of task i build_job_times()
job_d[(i,j)] dict Deadline of job j of task i build_job_times()
mapping[(i,j)] dict Processor index assigned to job (i,j) quantum_sps_mapping() → refined by refine_mapping_2a/b()
proc_jobs[x] dict of lists List of (i,j) jobs assigned to processor x build_proc_jobs() from mapping
freq_idx[(i,j)] dict Frequency level index for job (i,j) [0 = lowest, N_frq-1 = f_max] Initialised at N_frq-1; modified by aggressive.py
seg_k[(i,j)] dict Number of segments scheduled for job (i,j) [0 = mandatory only] Initialised at 0; incremented by greedy.py, swap.py

The Two Key Read-Write Variables

freq_idx and seg_k are the two mutable state variables that evolve through Phases 4–6. Every phase reads them and may modify them. The final values determine the schedule:

  • seg_k[(i,j)] = k means job (i,j) executes through segment k (cum[i][0] to cum[i][k] execution time)
  • freq_idx[(i,j)] = f means job (i,j) runs at frequency freq_set[f]

After Phase 6, these two dicts fully specify the schedule. print_schedule() reads only these plus cum and task metadata to produce the final output.

8. Adding a New Solver

Step-by-Step

1
Create V2/usrt/solvers/heuristic_v6.py with a def run(processors, tasks, B_BUDGET): function. Import whichever bricks you need.
2
Register it in V2/run.py:
SOLVERS = { ... "heuristic_v6": "usrt.solvers.heuristic_v6", # add this line }
3
Run it immediately:
PS C:\homogenous\V2> python run.py testcase.py heuristic_v6

Minimal New Solver Template

"""heuristic_v6 — experimental variant.""" from ..models import ALPHA, BETA, total_energy, total_utility from ..utils import lcm_list, gcd_list, build_cum, build_job_times, build_proc_jobs from ..mapping.quantum import quantum_sps_mapping from ..mapping.refine_mapping import refine_mapping_2b # optional from ..output import print_instance_summary, print_schedule from ..phases.energy_slack import compute_energy_slack from ..phases.aggressive import phase_aggressive_scaling from ..phases.greedy import phase_optional_segments from ..phases.swap import phase_swap_local_search def run(processors, tasks, B_BUDGET): # --- set up --- periods = [int(t['p_i']) for t in tasks] h = lcm_list(periods) quantum = gcd_list(periods) cum, N_seg = build_cum(tasks) N_tsk = len(tasks) N_prc = len(processors) freq_set = processors[0]['frequencies'] N_frq = len(freq_set) N_job = [h // periods[i] for i in range(N_tsk)] job_r, job_d = build_job_times(tasks, h) # Phase 1 mapping = quantum_sps_mapping(tasks, processors, h, quantum) proc_jobs, proc_jobs_map = build_proc_jobs(mapping) # (optional) Phase 1b — add/remove as needed mapping = refine_mapping_2b(mapping, tasks, N_prc, cum, N_seg, job_r, job_d) proc_jobs, proc_jobs_map = build_proc_jobs(mapping) # Init state freq_idx = {(i,j): N_frq-1 for i in range(N_tsk) for j in range(N_job[i])} seg_k = {(i,j): 0 for i in range(N_tsk) for j in range(N_job[i])} # Phases 3-6 E_init, E_slk = compute_energy_slack(seg_k, freq_idx, freq_set, cum, N_tsk, N_job, B_BUDGET) if E_slk < -1e-9: return phase_aggressive_scaling(seg_k, freq_idx, freq_set, N_frq, cum, N_tsk, N_job, proc_jobs, job_r, job_d, N_prc) phase_optional_segments(seg_k, freq_idx, freq_set, N_frq, cum, N_seg, N_tsk, N_job, proc_jobs, proc_jobs_map, job_r, job_d, tasks, N_prc, B_BUDGET) phase_swap_local_search(seg_k, freq_idx, freq_set, N_frq, cum, N_seg, N_tsk, N_job, proc_jobs, proc_jobs_map, job_r, job_d, tasks, N_prc, B_BUDGET) print_schedule(seg_k, freq_idx, freq_set, cum, tasks, N_tsk, N_job, mapping, B_BUDGET, label="v6 SOLUTION")
